Agent SAV e‑commerce

Traiter un retour ou un échange à partir d’un message client, puis reprendre le dossier après une coupure sans créer de doublon.

Du message à l’échange

« Le pull est trop petit, je veux le même en M. »

  1. Comprendre la demande

    Mistral Large 4 lit le message et en extrait une demande d’échange vers la taille M.

  2. Vérifier la variante et transmettre la demande

    Le code vérifie le stock avant d’enregistrer la demande. En cas de rupture, le chat propose un retour. Si la taille est disponible, elle est réservée et LangGraph attend la décision de la boutique.

  3. Attendre la confirmation du client

    Si la boutique valide la demande, le client reçoit un mail de démonstration avec des liens signés. Sa confirmation crée le retour et son récapitulatif dans une seule transaction.

Le LLM intervient uniquement pour interpréter la demande. Le code décide si l’échange peut être exécuté et effectue les écritures en base.

Et si la confirmation se perd ?

La boutique a enregistré le retour, mais la réponse n’arrive pas. LangGraph ne sait donc pas si l’opération a abouti. À la reprise, il réessaie avec le même identifiant de dossier. Cet identifiant sert de clé d’idempotence. La boutique retrouve le retour existant et renvoie sa référence.

Les tests vérifient qu’après la reprise, la base contient un seul retour, une seule réservation et un seul mail récapitulatif.

Ce que je veux mesurer

Le prototype tourne dans le terminal avec une commande fictive. Pour le portfolio, je veux comparer sur les mêmes cas un workflow à règles, un LLM qui appelle directement les outils et le workflow persistant. L’objectif est de voir quand le modèle aide à comprendre la demande et quand la reprise évite une erreur d’exécution.

  • Dossiers correctement résolus
  • Écritures erronées ou en double
  • Coût
  • Latence
